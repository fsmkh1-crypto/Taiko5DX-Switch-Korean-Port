# AGENTS.md

Operating rules for ChatGPT, Claude, or any other coding/research agent working on this repository.

1. **Read path is fixed:** read `AGENTS.md`, then `PROJECT_STATE.md`, then only the paths listed in `PROJECT_STATE.required_reads` for the current scope. The canonical chain is `AGENTS.md -> PROJECT_STATE.md -> PROJECT_STATE.required_reads`. Do not perform an open-ended conditional pre-read. Read other historical/detail documents only when a specific claim needs provenance.
2. **User execution gate:** discussion, review, planning, and status questions do not authorize analysis tools, modifications, builds, or commits. Start actual work only after an explicit signal such as `시작`, `해`, `진행`, or `ㄱㄱ`.
3. **One signal, one agreed scope:** an execution signal authorizes only the scope agreed at that moment. After that scope is reported, a fresh signal is required for the next analysis, modification, build, or migration stage.
4. **Analysis and modification are separate:** after analysis, report `확정된 사실 / 유력한 가설 / 미확정 사항 / 기각된 가설 / 관련 영향 범위 / 수정 제안` and STOP. The report itself is not authorization to implement.
5. **Reuse VERIFIED facts:** follow `docs/VALIDATION_POLICY.md`. A new chat/model/agent is never a revalidation trigger. Revalidate only on changed identity, contradictory evidence, inadequate provenance for the current decision, or a demonstrated flaw in the prior method.
6. **Root-cause-family rule:** once a common mechanism is identified, survey the affected data classes, code paths, call sites, descriptors, and analogous symptoms before proposing a fix. Do not patch one symptom in isolation.
7. **PC-patch-first rule:** when the Windows Korean patch already implements the behavior, inspect its actual replacement bytes, font strategy, mapping, pointer handling, helper/runtime descriptors, and data structures before inventing a Switch-specific solution.
8. **Source-grounded data:** proper names, Korean spellings, compact glyph codes, and translations available from the PC patch/font/canonical data must be taken from those sources, not guessed from romanization or screen appearance.
9. **Diagnostic discipline:** one root-cause family per diagnostic build. All proven instances of the same mechanism may be tested together; unrelated hypotheses must not be mixed. Failed and weakened hypotheses must be recorded.
10. **Document authority:** `PROJECT_STATE.md` is the sole project-resume authority. Domain specifications and canonical evidence keep their own narrower authority as classified by `docs/DOCUMENT_AUTHORITY_INDEX.json`. Historical “next step” text never overrides `PROJECT_STATE.md`.
11. **Artifact and transport discipline:** follow `docs/ARTIFACT_AND_PROVENANCE_RULES.md`. Separate semantic identity from transport identity, preserve historical transport provenance, and explicitly record failed transports. Do not use manual long binary/base64 connector payloads or progressively smaller blob fragments as a normal repository workflow. **For text Git blobs, use `create_blob(content=<exact text>, encoding="utf-8")` directly; never manually Base64-encode, split, or reassemble text. Base64 is reserved for genuine binary payloads.**
12. **GitHub/CI discipline:** follow `docs/GITHUB_AND_CI_POLICY.md`. Verify remote `main` at stage start, prefer local validation, batch one logical change into one commit, verify the remote result, use CI as an independent/final gate, and never force-push.
13. **Build/runtime provenance:** every diagnostic/runtime/release artifact follows `docs/PROVENANCE_POLICY.md`. Generated binaries stay out of Git; large artifacts belong in the project Google Drive and are bound by hashes and reproducible source/report records.
14. **No silent accounting shortcuts:** no silent source omission, no silent UNKNOWN authorization, no denominator exclusion without verified exclusion evidence, and no synthesis of missing canonical payload rows from IDs/counts.
15. **Stage closure:** update the current state and the relevant validation ledger for meaningful work, record rejected approaches, report the authorized scope, and STOP. A later stage requires a fresh user signal.
