## 4. Working analysis method

For residual localization/text obligations, use this evidence order:

1. **Switch structural evidence**
   - physical object identity;
   - logical JP entry identity;
   - owner/cardinality;
   - storage/language domain;
   - table/sequence relation.

2. **Actual PC Korean-patch mechanism for that occurrence**
   - inline replacement;
   - suppression/zero replacement;
   - pointer redirection;
   - formatter/composite treatment;
   - other runtime layer when applicable.

3. **Actual PC Korean replacement evidence**
   - exact replacement bytes;
   - same-original variants at other PC RVAs;
   - neighboring PC source sequence.

4. **Switch logical-entry neighborhood**
   - neighboring JP entries;
   - table role;
   - sequence correspondence.

5. **Linguistic/semantic role**
   - standalone noun/label;
   - counter/unit;
   - formatter component;
   - name/yomi element;
   - UI command/category;
   - fragment of a larger expression.

6. **Consumer tracing only when ambiguity remains**
   - per-consumer tracing is a last resort, not the default first step.

Language is corroborating evidence for structure, not a substitute for structure.

## 5. Mandatory safety rules

The following shortcuts are forbidden:

- linguistic meaning alone does not select a Switch target;
- PC mechanism correspondence alone does not authorize a Switch target or action;
- identical Japanese text does not imply identical semantic object/use;
- replacement agreement alone does not prove target binding;
- unique full-JP value match alone does not prove final `DIRECT_PORT`;
- `TARGET_RESOLVED` does not imply `WRITE_SAFE`;
- already materialized L1/L2/L3/L4 membership must not be recomputed merely because the chat/model changed.
