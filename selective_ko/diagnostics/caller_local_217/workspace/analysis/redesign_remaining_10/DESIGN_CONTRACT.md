# Caller-owned Korean grammar: exact 143-occurrence design contract

Policy ID: SUPPLEMENTAL_CALLER_OWNED_KOREAN_GRAMMAR_DESIGN_20260923
Authority: the user's explicit correction that this is a redesign after repeated legacy failures, followed by execution authorization. This is a supplemental read-only design decision, not a canonical repository policy amendment or an implementation grant.

## Acceptance claim

The target is intelligible, source-grounded Korean at the indexed caller boundary, preserving propositional and required dynamic meaning. Exact legacy PC formatter output, selector-dependent register and the historical malformed Switch output are not the target. A missing exact historical executable is not a gate for this design claim.

Caller-authored Korean register owns the redesigned boundary. This intentionally removes selector-dependent grammatical variation there; do not describe it as behavioral equivalence. Person identity, address content, item/place values, conditional source meaning, tense/aspect, polarity, modality, beneficiary relationships and required actions must remain represented in the target or preserved calls.

## Rules

1. Consume the frozen source-owner and PC Korean command binding. Read the actual paired Japanese clause and PC Korean wording. Root labels alone never decide admission.
2. Remove a grammar call only when the retained Korean wording already expresses the required meaning and grammatical construction. A negative-labelled Japanese formatter may be redundant in Korean 없/않겠, an apology or a request; justify the exact clause instead of applying a root-global rule.
3. Where an authored Korean stem and ending require morphological completion, record the exact bounded recomposition and its reasoning. Label composed targets as design judgments, not independently attested full phrases. Use existing PC wording and Japanese clause function; do not invent names or new narrative content.
4. Hold a row when removal loses a lexical predicate, uncertainty/permission/beneficiary contribution or an unresolved register decision. Do not use apparent local fluency as the only criterion.
5. Preserve every non-target byte interval, caller header/branch representation, other dynamic token/argument, order and line break. A source-hold row stays held. Preserve root files themselves: this is a caller-local design, never a global root erasure.
6. Compose multiple scoped edits per owner for review. Mark unresolved scoped rows in that owner; do not implement a partially decided owner by accident. Remaining unscoped grammar calls are not silently admitted or closed.

## Evidence levels

BOUNDARY_DESIGN_DECIDED means the assistant has adjudicated an exact boundary target under this contract using the paired sources. It does not mean user approval of a final implementation, WRITE_SAFE, frozen validation-ID closure, full-sentence semantic completion or runtime PASS.

Implementation still requires a separately authorized exact edit manifest, source guards, applicable writer/relocation contracts and product verification. Existing transport receipts may be reused only to the extent they cover the unchanged bytes; new target bytes would need their own checks at that stage. Do not rerun old transport work now.
